# The cross-page coherence gate is an off-device contrastive-accuracy test on hand-authored minimal pairs

ADR-0002's acceptance gate — the JA-EN zero-pronoun contrastive set named in #30 — is a set of **minimal pairs**: a source whose subject is elided and resolvable only from the previous page, one **correct** English target, and one **corrupted** target that flips only the disputed referent. The model passes a pair when it assigns higher probability to the correct target than to the corrupted one. Passing the gate is **directional**: contrastive accuracy with session context must beat accuracy with it blanked, on the same pairs. Scoring runs **off device** on desktop llama.cpp, which exposes log-probabilities natively; the production translation path stays generation-only. This ADR fixes that contract. The corpus and the runner are build work for the post-map effort, not built here.

Before this, ADR-0002 ended with `Acceptance gate: the JA-EN zero-pronoun contrastive set from #30` and nothing that said what the set was, how it scored, or what passing meant. #47 (ADR-0004) then carved the whole question out of the main translation harness on purpose — its cases are single, non-consecutive pages, so `sessionContext` is empty everywhere and cross-page referent resolution is measured nowhere — and #52 deferred all adequacy/fluency ranking to "#30's contrastive set and a possible future COMET-or-judge metric." This set is the map's one home for cross-page coherence measurement, and until now its shape was a pointer to a research note.

## Considered Options

**Reuse ADR-0004's generate-and-check harness with a coherence metric bolted on.** Rejected. A contrastive test does not generate — it scores the probability of a *supplied* target, a different mechanism from `translate()`-and-check. And #52 already established this corpus scale carries no continuous quality metric worth significance-testing; a coherence metric on ~150 generated lines is the power wall #52 hit, in another costume.

**Score contrastive accuracy on-device.** Rejected. The LLM path — ADR-0002's sole design target — has no forced-target scoring: `nativeGenerate` (`ml/src/main/cpp/llama_jni.cpp:171`) is the only inference export and it discards logits before they reach Kotlin. Exposing them is new native/JNI work, and a design-acceptance gate is not a shipped user path that would justify it. OPUS-MT's ONNX decoder *can* teacher-force a target in pure Kotlin (`OpusMtTranslator.kt:157` already surfaces per-step logits), but OPUS-MT collapses to per-line with no session context (ADR-0002), so a coherence gate on it measures nothing.

**Build the pairs from consecutive OpenMantra pages and measure a generation delta** (run with context, run without, diff the output against the reference). Rejected. #47 already rejected building "a second, weaker version out of consecutive OpenMantra pages" because it measures the same thing worse, and it needs exactly the sensitive quality metric on a noisy ~150-line corpus that #52 ruled unpowerable.

**A fixed absolute accuracy bar** (e.g. ≥0.7 correct-over-corrupted). Rejected. Genuine cross-page zero-anaphora cases in a five-volume corpus are scarce — tens of pairs, not hundreds — and #44's power analysis plus #46's "first measurement is the baseline, no absolute bar" precedent both say a corpus this size cannot support a tight threshold. The claim a contrastive set makes is inherently a *delta*, so the gate is a delta.

**Fold #30's doc-level COMET second step into this ADR.** Deferred, not decided here. #30 paired the contrastive set (near-term) with doc-level COMET as a CI-only second step, and #52/ADR-0004 already park a "future COMET-or-judge metric" as deferred. One ADR, one mechanism.

## Consequences

**A separate runner, off device.** The gate lives in its own case type (e.g. `eval/translation-coherence/`), not as a mode on the ADR-0004 scorer — the scoring mechanism is forced-target log-probability, not generate-and-check. It runs the chosen GGUF on desktop llama.cpp with log-probs, assembling the page prompt exactly as ADR-0002 specifies. **ADR-0002 owes no new native work**: the production path stays generation-only, and Q2's earlier "on-device forced-target scoring is a build precondition" caveat is dissolved by moving the gate off device.

**Corpus recipe.** Mine OpenMantra's consecutive-page runs for lines whose subject is elided and resolved by the previous page's antecedent. The **correct** target is OpenMantra's own English annotation. The **corrupted** target is a hand-authored single-referent flip — the wrong antecedent, changing nothing else. Corpus size is not fixed here: it is whatever the corpus genuinely yields, reported as N at build time.

**Authorship is a build precondition, and it is the risk.** Writing a corrupted target means picking a *plausible* wrong referent and confirming the Japanese is genuinely ambiguous without the prior page — this needs JA-EN competence and cannot be fabricated by heuristic. This map has already been burned once by heuristic ground truth (#44's `speech`/`narration`/`sfx` labels, invented by `generate-cases.py:label_for()`). The pairs are authored by a competent annotator or the gate measures nothing; that is recorded here so the post-map build does not rediscover it.

**Passing is directional.** Contrastive accuracy with session context present must exceed accuracy with it blanked, on the identical pair set, tested paired (McNemar). Chance (0.5, one corrupted target per pair) is the floor. It is a direction / regression gate — "session context provably helps referent resolution" — not a fine-grained quality bar. The first run is the recorded baseline. Scaling to an absolute accuracy bar waits on a larger corpus than this map builds.

**The gate is defined now but cannot run until ADR-0002 is built.** `TranslationEngine.translate` still carries `@Suppress("UNUSED_PARAMETER")` on `sessionContext` and never reads it (#47), so today the set would score identically with and without context. Defining the contract does not exercise it; the gate goes live once the ADR-0002 architecture is built in the post-map effort.

**No in-map ticket is blocked on this.** #35 selects among gate-passing engines on #26's non-quality axes (RAM, latency, size, licence), not on coherence (#52). The corpus build and the runner are post-map work that gates ADR-0002's *architecture*, not any remaining decision on this map. ADR-0002 gets an amendment pointing here in place of its dangling gate line; doc-level COMET stays #30's deferred second step.
